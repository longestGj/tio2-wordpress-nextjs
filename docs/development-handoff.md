# D16 通用开发交接清单

适用于“批准输入 → Gate8 开发 → 独立代码复审 → Gate8 合入 `develop`”。生命周期见[开发流程](development-workflow.md)，方法和环境见[内部执行](development-execution.md)。后续发布使用另一条[独立发布流程](release-workflow.md)。

## 1. 批准输入交给 Gate8

| 输入 | 接收检查 |
|---|---|
| 网站、语言、页面/功能、路径、范围与限制 | 与网站登记和目标开发环境一致 |
| 当前批准入口和版本 | 来源可读、组合有效、替代关系明确 |
| 文案、业务事实和行为 | 字段语义、基数、链接动作、条件与失败行为足够明确 |
| 视觉与资产 | 原始设计、响应式状态、版本、权属和缺失处理明确 |
| 数据、CMS、SEO、缓存与媒体 | 归属准确网站和 scope，不借用另一站配置 |
| 接受条件 | 保留已有 ID、预期、正负向、交互、隔离和失败判据 |
| 共享消费者 | owner、消费者、兼容约束和回归范围明确 |
| 授权与终点 | 本次负责到技术交付或合入 `develop`，外部动作单独记录 |

Gate8 在任务记录中保存批准组合、`develop` 基线、任务分支、允许路径、测试映射、依赖和未决项。缺口只阻止依赖步骤；业务冲突返回决定方，技术问题在原范围处理。

## 2. Gate8 交给独立代码复审

交付必须锁定同一个对象：

- 任务、网站、批准版本和接受条件；
- BASE、实现 HEAD、工作树状态和改动路径；
- 单元、集成、任务 E2E、视觉检查和消费者回归证据；
- 实际运行 URL、Build、CMS/数据、配置和证据身份；
- 模拟与真实外部效果的边界；
- 已知开放项、恢复定位和下一责任方。

复审者只读检查差异和证据，给出通过或可执行问题。身份无法锁定、环境不可访问或证据缺失时，只能签署不受影响部分。反馈必须给出问题 ID、复现版本、环境、现象、预期和证据。

## 3. 返修与 `develop` 合入

Gate8 对技术反馈执行最小返修，保存新的源码与运行身份、定向红绿证据和影响回归，再请求复审。候选变化后旧结论按影响范围失效；旧证据保留并标明替代。

复审通过后，Gate8 重新核对 `develop` 与来源 HEAD，串行合并准确实现，验证实际合并结果，并使用[开发回执模板](templates/development-receipt.md)记录 `MERGED_TO_DEVELOP`。准备材料、送达、复审通过、合并和回执是不同事实。

开发回执进入 Git 后，本交接结束。它只作为发布负责人以后核对实际差异的输入；没有独立发布指令，不启动 `main`、预发布、打包或远程操作。
