# CMS 内容比对实现计划

> 使用 subagent-driven-development 执行独立采集模块，主控串行集成校验，最后独立复审。

目标：落实用户批准的各自清单验证、同口径实际 CMS 内容比对；不同内容阻止 frontend-only。

方案：旧接管摘要继续验证生产连续性；新增只读、跨数据库 ID 稳定的发布内容摘要，覆盖发布页面字段、meta 与分类。新增候选绑定的补充证据，保留旧 CMS identity 与 proof 原始字节。不得把历史证据改写为新通过。

- [ ] 采集模块及 TDD：共享 PHP 内容摘要与 Python 有界 Docker 读取入口，测试字段变化、顺序、跨站、ID 差异和异常。
- [ ] 校验集成及 TDD：独立校验原始迁移清单和候选预发布清单，补充证据绑定候选/旧 identity/新采集快照；新生产快照与预发布一致才通过。旧缺失证据拒绝。
- [ ] 本地补充证据采集工具：核对候选原件、CMS 容器挂载及源码身份，输出仅哈希和身份，不写 CMS。操作说明要求重新验证绑定快照的预发布，不沿用历史通过宣称当前通过。
- [ ] 相关测试、独立审查、合并 develop、开发回执；不修改 main 或生产。

历史 counts.seedFiles 是已记录脚本数量，不再作为两环境内容相同的证明。预发布的 orderedSeedHashes 仍须逐字节对应自己的清单及归档，原始接管仍须对应自己的已保护日志和文件。内容摘要不比较数据库 ID 或编辑锁；未知业务字段保守纳入，以误拒绝代替漏检。
