# TiO₂ Local WordPress + Next.js Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and verify a repeatable local WordPress + WPGraphQL + Next.js environment that renders two isolated TiO₂ sites from one codebase and remains stable with at least 500 synthetic pages per site.

**Architecture:** Docker Compose runs MariaDB and one WordPress CMS for two fully independent site content sets; a repository-owned plugin enforces unique site ownership and deterministic public routing. One host-run Next.js 16 application resolves a validated `SITE_ID`, queries only that site's content through a typed GraphQL adapter, pre-renders core routes, uses ISR for long-tail routes, and exposes per-site signed preview/revalidation endpoints. Optional TiO₂ CPT fixtures validate the extensible Schema but are not an MVP page dependency or shared invalidation graph.

**Tech Stack:** Node.js 24, npm, Next.js 16.2.x, React 19.2.x, TypeScript 5.9, Vitest 4, React Testing Library, MSW 2, Playwright, WPGraphQL, ACF, WordPress on PHP 8.3, MariaDB 11.4, Docker Compose.

**Spec:** `docs/superpowers/specs/2026-08-23-tio2-wordpress-nextjs-two-site-design.md`

## Global Constraints

- Use one Next.js application and exactly two local site IDs: `tio2-a` and `tio2-b`.
- Unknown or missing `SITE_ID` must fail validation; never fall back to another site.
- WordPress content reads use WPGraphQL cursor pagination with at most 100 nodes per request.
- WordPress internal slugs are site-prefixed; public paths are site-local.
- Every managed Page/Post has exactly one valid `site_scope`; ordinary edits affect only that owning site and never fan out.
- Generated GraphQL types are committed and are not regenerated by the ordinary `build` command.
- Preview and revalidation endpoints require independent secrets.
- Preview and non-production pages emit `noindex`.
- Core routes are pre-generated; long-tail routes use on-demand ISR and precise cache tags.
- Tests precede implementation for every behavioral change.
- Each task ends in an independently reviewable commit.
- Local acceptance includes at least 500 synthetic pages per site.
- Do not add Turborepo, Redis, WordPress Multisite, automatic DNS, or production credentials.

Architecture correction approved by the user on 2026-08-23: the sites share code, Schema, and the CMS instance only. They do not require shared page/entity content or a shared dependency graph.
