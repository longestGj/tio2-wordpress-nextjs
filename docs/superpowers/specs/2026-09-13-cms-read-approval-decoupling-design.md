## 2. 已确认事实

- 当前前端在构建时预渲染并读取 WPGraphQL；保持此方式。
- `legal-pages-v01.php` 的查询调用批准合同比较；`legal-pages-v01-dto.ts` 又进行同类比较，并固定正文分节数量。只改 PHP 会把失败移动到前端。
- `content-release-validation.php` 与 TypeScript 对应文件按批准对象和可编辑路径进行递归比较。非允许路径的值、数组数量和多项元数据必须与批准对象一致。
- 同类校验用于首页、产品、市场、资源、文档、联系、询盘及法律页面，不应仅为 Cookie 页面增加例外。
- 内容写入/导入与读取使用了部分相同的校验入口；直接放松共享函数可能扩大写入能力。
- 最新生产只读输出：法律合同可读、三条记录齐全，三条均 contract_mismatch；具体字段差异尚未取得。因此本方案不声称数据库文案错误或存在某个确定字段差异。

## 3. 选择

采用显式运行时结构合同，而非继续扩大可编辑文本路径表。

不采用“所有字符串都允许变化”：字符串也可能是网站身份、路由、表单动作、媒体地址或安全控制。

不采用取消构建时 CMS 查询、动态渲染全站或静默回退代码批准稿：这些改变运行方式或掩盖错误，不是本轮目标。

## 4. 责任边界

### 4.1 CMS 内容与批准

- 内容编辑、业务审核和发布属于 CMS/内容交付流程；技术校验通过不是业务批准。
- 读取只消费对应站点已发布记录，不能读取草稿、跨站 fallback 或用代码中的旧文案替换 CMS 值。
- 现有 seed、导入、预发布审批材料和历史批准文件保留原样；不改写法律正文、不将旧记录自动标记为已批准。
- 不新增 CMS 审批系统；现有内容写入仍遵守现有授权和验收流程。

### 4.2 运行时读取合同

由独立、明确命名的结构合同定义读取条件，不以完整批准内容 JSON 作为实际值的比较模板。

保留：

- `site_scope=tio2-my`、已发布状态、页面类型、唯一记录、合法页面 ID、语言和已登记路径。
- 渲染所需字段、JSON 类型、支持的结构版本、必要集合唯一性和明确的资源长度限制。
- URL 协议与目标限制、表单工作流和内部路由绑定、媒体来源限制，以及现有 HTML/Markdown 安全解析。
- 对模板确实必要的关系约束，例如引用对象存在、同一集合 ID 不重复。

不再要求：

- 标题、正文、SEO 文本与批准文件中的文字相同。
- 法律 Markdown 标题、更新时间或段落数等于批准稿；只有解析器和 UI 实际支持的结构约束保留。
- 内容修订标识、批准日期和审批状态与打包时批准稿相同。

元数据不能笼统删掉或一律放行：逐字段区分正文、技术身份、安全/行为控制和批准证据。纯批准证据不参与读取放行；若旧字段同时控制渲染或行为，先拆出技术含义并覆盖测试。统计脚本是否运行仍由实际配置和用户同意控制，不由法律文案状态字符串控制。

### 4.3 两端一致

- PHP resolver 在返回前验证站点、发布状态及运行时合同。
- TypeScript DTO 把 GraphQL 返回视为不可信输入，验证同一运行时合同后输出 CMS 值。
- 页面集合/路径元数据与批准文案分离。DTO 类型不再用整份批准对象作为隐含运行时校验依据。
- 结构规则可以共享声明式数据及测试向量，但不引入通用审批平台或动态执行规则。
- 缺失字段、错站、非法链接、无法安全渲染等仍明确失败，不吞异常、不虚构默认内容。

### 4.4 写入与发布不被顺带放宽

- 保留现有内容写入合同、鉴权、备份和恢复约束。
- 从查询专用入口迁出批准比较，而不是改变 `tio2_my_content_matches` / `matchesInstalledContent` 对所有调用者的含义。
- 如果某个 validator 同时服务查询和导入，建立明确的读取 validator，让导入继续使用原约束；不把读取放宽传播给发布授权。
- 前端部署仍验证源码、配置、CMS 程序兼容性与回退身份。此次不取消这些哈希和登记检查，也不承诺构建完全不依赖 CMS。

## 5. 实施分组

1. 建立调用矩阵和运行时合同基础：列明每个受影响字段与查询/DTO/写入消费者。所有字符串不能按一个宽松规则处理。
2. 法律页作为第一条完整纵向链：PHP、DTO、Markdown 解析/组件消费、查询测试同时迁移；验证修改正文/更新时间/正常分节仍可渲染，错站/路径/危险 Markdown 仍拒绝。
3. 按页面族迁移其余 MY 查询和 DTO：首页/应用/联系，产品/市场，文档/资源/编辑内容，表单页面。每组有完整读链测试，不留下 PHP 已放行但 TS 仍比较批准稿的半迁移。
4. 集中运行目标 CMS 查询和相应前端回归，形成准确范围清单；迁移遗漏作为阻断项，不宣称全站解耦完成。

主要代码入口：`wordpress/plugins/tio2-site-model/includes/*`、`lib/wordpress/*-dto.ts`、`lib/legal/markdown.ts`、对应页面组件、相关 PHP/TypeScript 测试。具体更改文件随每组调用矩阵固定；不做无关清理。
