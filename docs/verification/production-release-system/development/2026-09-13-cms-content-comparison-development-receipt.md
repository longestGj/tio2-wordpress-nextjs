## 实现与原因

原始生产执行清单与预发布清单不同，不再以两者字节相等推断内容相等。保留各自文件字节、候选归档、原始计划和 PUBLIC_READY 日志验证，并要求新的候选绑定内容证据。

共享只读采集器覆盖已发布的所属页面字段、业务 meta 和分类，稳定处理数据库 ID 与查询顺序；同键 meta 值保留实际优先顺序。采集器不输出内容明文、不写 CMS。

补充证据工具核对准确候选、源码、CMS 插件挂载、前后快照和近期真实测试记录，拒绝覆盖旧证据。原始 proof/identity 不改写；通过数不得少于原 proof 的 browserCases，失败或跳过不能通过。接管后持久化完整快照摘要，兼容前台每次读取基线时继续核对，防止接管后业务字段漂移。
