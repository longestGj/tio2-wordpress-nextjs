# D16 内部开发与测试执行

本文件只描述任务分支上的 TDD、单元/集成/任务 E2E、技术复审和开发环境。开发职责与 `develop` 合入见[开发交付流程](development-workflow.md)；预发布、候选包和生产动作见[独立发布流程](release-workflow.md)。

## 1. 任务记录

每个任务在开始时固定网站、任务主体、批准输入、接受条件、`develop` 基线、分支、允许修改路径、消费者、开发环境和授权边界。记录中把“要求什么”“由哪个模块负责”“怎样观察结果”连起来，避免只列文件或测试数量。

状态分别记录：未开始、实现中、技术验证通过、独立代码复审通过、返修中、已合入 `develop`。开发记录不推断后续环境状态。

## 2. TDD

行为新增、缺陷修复和有风险的重构执行红绿重构：

1. 先从批准条件或明确技术合同写出一个能观察目标行为的测试。
2. 运行测试，确认它因行为缺失或错误而失败；语法、导入和环境故障不是有效红灯。
3. 写让该测试通过的最小实现。
4. 重新运行同一测试并确认通过，再运行直接相关回归。
5. 需要时重构，并保持测试通过。

已有行为本来正确时，已有测试的通过只能记为基线或回归，不能倒写成红灯。缺少历史红绿证据时标为后补回归。测试不得调用被测逻辑生成预期，也不得用源码字符串或无行为的 mock 代替真实结果。

## 3. 测试层次

| 层次 | 适用问题 | 证据边界 |
|---|---|---|
| 单元 | 纯函数、DTO、校验、状态转换、错误映射 | 快速定位单一行为；不证明组件已接线 |
| 集成 | 查询到 DTO、API 到服务、组件到接收适配器、CMS scope | 观察真实组件连接；模拟外部端时明确模拟边界 |
| 任务 E2E | 本次改动影响的关键用户旅程、路由、表单状态或跨页关系 | 绑定实际任务 Build、网站、URL、数据和视口 |
| 人工视觉/交互 | 完整页面、响应式、焦点、菜单、弹窗和图片 | 保存实际看到的状态；不由 DOM 焦点或截图数量代替 |

每项接受条件必须有验证去向，但不要求机械地同时建立所有层次。共享实现先验证本身，再对受影响网站运行有限消费者回归。真实外部提交需已有适用授权，并把 provider 接受、Thank You 和实际收件分别记录。

## 4. 开发环境

| 用途 | 身份与边界 |
|---|---|
| 多站开发 | `tio2-a` / `tio2-b` / `tio2-my` 使用登记的网站身份和各自端口，不跨站 fallback |
| 人工 feature runtime | 从租约池申请端口，绑定网站、worktree、Build 和保持/释放条件 |
| 自动化 Next/HTTP fixture | 优先使用 OS 端口 `0`；需要数字端口时使用自动化租约池 |
| 开发 WordPress | canonical 开发 Compose 与数据；共享写入串行并可恢复 |
| 隔离 WordPress 测试 | 使用唯一 `d16-test-*` 项目；数据库不暴露主机端口 |

固定端口、租约、owner 核对和恢复命令见[运行端口操作手册](runtime-ports.md)。只停止本任务启动且身份核实的进程；不能杀掉端口占用者、重建别人的 Compose 项目或清理共享卷。

每个并行任务使用独立 Build 目录、测试输出和运行身份。worktree 只隔离源码，CMS、端口、Docker 项目和证据仍需单独隔离或串行。

## 5. 选择与运行检查

正常开发运行与变化及依赖直接相关的检查：

- TypeScript、PHP 或 Python 合同变化运行对应单元和类型检查；
- 组件连接或数据流变化运行集成测试；
- 用户可见流程变化运行少量关键 E2E 并查看适用视觉状态；
- 共享基础设施变化核对消费者并运行有限回归；
- 纯文档变化只检查链接、差异与规则一致性。

命令回执记录工作目录、代码 commit、网站、环境、前提、执行日期、通过/失败数量、跳过及原因。平台设施不可用导致的跳过如实报告，不能改写为零跳过。

测试失败先判断行为缺陷、测试缺陷还是环境前提。行为缺陷先写或保留能复现它的失败测试，再修复；偶然重跑通过不关闭问题。环境失败保留日志并只阻止依赖该环境的结论。

## 6. 技术复审

Gate8 冻结 BASE/HEAD 和证据后调用独立代码复审。复审检查批准范围、架构边界、测试真实性、错误路径、跨站隔离、共享消费者和未决项。审查者返回可执行问题或通过结论，不直接修改业务代码。

返修必须形成新的准确 HEAD，并运行针对问题的测试和受影响回归。复审通过只证明该开发候选具备合入 `develop` 的条件；Gate8 仍需核对实际合并结果并写开发回执。

## 7. CI 与恢复

当前仓库提供可显式调用的测试、构建、运行控制器和证据脚本；文档存在不表示提交触发器或远程 CI 已安装。开发 CI 的边界是任务分支与 `develop` 合并结果，检查集合按影响面选择。

长任务记录 BASE/HEAD、已完成步骤、最近命令结果、返修轮次和开放决定。恢复时先用 Git 与实际运行身份核对台账，不重复执行已经稳定完成的工作，也不覆盖其他任务的未提交修改。

开发 Build 和临时数据不是发布制品。开发侧只提供 `MERGED_TO_DEVELOP` 回执和可追溯证据，供独立发布流程在新的指令下重新冻结和验证。
