## 接单阅读

1. 在[网站登记](../site-registry.md)确认网站及策划归属。
2. 读取对应网站README、本次领域及相关journeys，按sources定位有效批准依据。
3. 核对源资料的当前有效版本；将实际使用的路径、版本/哈希与接受条件固定在任务记录。

## 扩展与维护

- 新网站增加`<site-id>/README.md`；新增业务领域增加`domains/<domain>/README.md`。先有具体内容再建目录，不批量生成空模板。
- 网站README维护领域导航，`journeys.md`连接跨领域流程，`sources.md`定位依据；领域README维护目标、规则、状态、数据语义、场景及实现映射。内容增长后再拆文件。
- 已有业务增加页面或功能时更新原领域；按开发任务新增的是证据记录，不是另一份长期业务定义。
- 规则区分“批准依据”“当前实现”“验证记录”。实现和测试不能反向证明批准；历史PASS不代表当前PASS。
- 业务摘要引用准确来源，枚举、长文案等直接引用原合同，避免维护两套正文。发现来源冲突记录具体差异、影响及待决定责任，不自行合并解释。
- 交付包、历史设计、测试夹具及CMS配置保留原位置。业务变化在对应任务中同步本目录及来源关系，不改写历史证据。
- 跨站共享规则仅在确认语义一致、明确维护方后提取。未整理不代表没有业务或可以套用其他网站规则。
