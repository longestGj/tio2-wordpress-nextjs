# Malaysia 跨领域业务流程

状态：询盘相关流程样稿。场景编号仅为D16导航，不替换交付合同的接受条件ID；不是已经通过的测试报告。规则见[询盘领域](domains/inquiries/README.md)，来源见[sources](sources.md)。

| 流程 | 起点→终点 | 应观察的结果及边界 |
|---|---|---|
| MY-J01 产品询盘 | 已接入的产品入口→询盘预填→补充信息→提交结果 | 合同允许的产品正确预填且可编辑；合法输入才能提交；来源与实际入口一致。须核对具体产品页面CTA，不能推断全部产品均已接通 |
| MY-J02 内容导流询盘 | 已接入的应用/市场/资源入口→询盘→提交结果 | 合同允许的应用、目的地或上下文正确传递；不把目的地解释成公司所在地；非法参数不变成有效业务值 |
| MY-J03 直接询盘与恢复 | 直接打开询盘页→填错→纠正→提交失败→重试结果 | 错误可识别，其他输入保留，提交中防重复；失败不能显示收到请求，重试后按实际响应显示结果 |
| MY-J04 实际接收 | 用户提交→真实服务商接收→指定邮箱收到正确内容 | 需真实发送授权、目标账户及人工收件证据；普通模拟流程不能证明，未验证不得宣称闭环 |

任务分支在开发环境选择相关流程；develop组合在开发环境核对相关跨页流程；main预发布验证实际构建、配置、CMS及适用流程。每次绑定精确版本、数据、真实/模拟环节和证据。哪些入口已经有效接入由当次合同与运行确认；不为通过测试虚构链接或外部结果。
